# 营养膳食助手（Vue3 + TypeScript 前端原型）- 产品需求文档

## Overview

* **Summary**：从零构建一个 **Vue3 + TypeScript 响应式网页应用**，**聚焦高血压人群的日常膳食管理**，面向 **50 岁以上关注血压健康的人群**（核心画像为轻度高血压患者，兼顾"不清楚自己有没有高血压"的风险人群与无高血压的预防人群），演示"登录 → 首次健康引导（高血压分流测评）→ 拍照 → 识别食物与分量 → 以低钠高钾（DASH）为核心的营养计算与规则解释 → 替换食谱 → 保存后血压指标联动"的完整闭环，并提供手动录入血压、规律服药打卡、DASH 每日达标、血压周报总结四项血压专属能力。接口层 mock/真实后端双实现、签名一致、环境变量一键切换：mock 模式零依赖本地演示，真实模式对接队友开发的 FastAPI（`127.0.0.1:8000`）。

* **Purpose**：笔记本浏览器本地演示与答辩使用，验证产品形态（首次健康分流 + 血压计/手环/体脂秤/智能餐盘的硬件联动故事 + 手动血压记录与服药管理）；本期前端不实现后端（由队友按本 spec 附《前端-后端接口契约》开发），不接入真实硬件，不误导用户为真实医疗数据。

* **Target Users**：50 岁以上、能自理操作电脑/手机的中老年人：可能已确诊高血压，也可能"不清楚自己有没有高血压"需要简单引导判断（主要操作者为用户本人或其照护人/答辩观众，在笔记本上演示）。

## Goals

* 首次登录用**尽量少的步骤**完成健康状况初判：是否高血压（是/否/不清楚三分支，"不清楚"走症状问卷分档）+ 基本信息收集（身高体重、职业、饮食偏好与习惯等），后续营养建议与健康页据此个性化。

* 跑通完整演示闭环：拍照（或相册）→ 识别确认 → 营养结果与口语化建议 → 保存这餐 → 健康页/周报数据随之变化。

* 适老化：大字、高对比、大点击区、口语化文案、语音播报，中老年用户能看懂、无压迫感。

* 数据可信：mock 食物成分提取自仓库 `data/` 真实数据集，规则阈值附证据出处；问卷明确声明"不能代替测量与医生诊断"。

* 工程可交付：`npm run dev` 直接运行、`npm run build` 零报错、`vue-tsc` 类型检查零错误、Vitest 全绿、mock/真实后端用环境变量切换；husky 本地钩子 + GitHub Actions 远端门禁。

## Non-Goals

* 前端不内置/不训练图像识别模型（真实识别由队友 FastAPI `/api/recognize` 提供，前端交付完整上传链路、错误降级与手动修正，见 FR-49）；不实现真实后端（队友负责 Python 3.13 + FastAPI，前端交付契约文档与双实现接口层）；不接入真实硬件（全部为前端 mock/浏览器能力模拟）。

* 不做第三方登录；不做云同步。**账号体系保留**：mock 模式在本机模拟注册/登录与按账号隔离数据，真实模式走 FastAPI token 鉴权（见 FR-48）；**短信验证码的网关、发码与频控由后端负责，前端交付验证码登录 UI、接口契约与 mock 演示码（见 FR-50）**。

* 不做完整离线同步引擎：真实后端模式下网络失败只给中文错误提示并保留本地草稿，不做冲突合并/后台重放队列。

* 不配置 Storybook；不做 IE 兼容、不做小程序/App 适配；仅兼容最新版 Chrome/Edge。

## Functional Requirements

### 导航与整体

* **FR-1**：5 个一级入口（拍照 / 健康 / 周报 / 食谱 / 我的）。宽屏（≥1200px）为左侧固定竖向导航栏（图标 + 中文文字）；窄屏（<768px）为底部 Tab 导航；中间宽度自适应。结果页由首页流程进入、不在主导航中；"我的设备"为"我的"下的二级页。导航层级不超过 3 层。

* **FR-2**：全局固定位置提供"语音播报"开关；每页只有一个主操作按钮。

### 拍照记录页（首页 `/`）

* **FR-3**：大主按钮"拍一拍今天的饭菜"，调用 `navigator.mediaDevices.getUserMedia` 打开摄像头，视频预览区最大宽 720px 居中，含拍照按钮；同时提供"从相册选择"上传兜底（localhost/HTTPS 约束下摄像头不可用时走相册不报错）。

* **FR-4**：拍照/选图后前端 canvas 压缩到最长边 1024px、JPEG quality 0.8；**手机相册照片须做 EXIF 方向校正（纯前端实现，不引运行时依赖）**，避免上传/预览时横置；真实模式上传前压缩逻辑一致（详见 FR-49）。

* **FR-5**：模拟识别：1.5 秒 loading 动画后返回 mock 多道菜结果；内置 5 种识别场景，按顺序循环（首次随机），场景按**钠含量与 DASH 友好度**梯度设计（具体菜品以 mock 成分表实际可计算项为准，允许为高钠场景增补 1–2 个腌制/酱卤菜品并注释估算来源）：

  1. 重盐大餐：白米饭 200g + 酱烧/红烧菜（如土豆炖牛肉重酱汁 180g）+ 腌咸菜或酱拌菜 50–100g（目标单餐钠 >1500mg、远超 800mg 单餐参考）
  2. 家常均衡：米饭 150g + 清蒸鲈鱼 120g + 白灼油菜 150g（钠约 600–800mg，接近参考线）
  3. 咸粥早餐：白粥 250g + 馒头 100g + 煮鸡蛋 50g + 佐粥咸菜 50g（高钠、蔬果与优质蛋白不足）
  4. 连汤咸面：煮面条 200g + 番茄鸡蛋浇头（连咸汤，钠偏高、钾不足）
  5. DASH 健康餐：燕麦饭/杂粮饭 180g + 西兰花炒虾仁 180g + 清炒菠菜 150g（低钠高钾，目标钠 <500mg、钾显著高于其他场景）

* **FR-6**：识别确认区：每道菜显示名称、置信度、分量选择（小/标准/大三个大按钮，映射不同克数，如 0.7/1/1.3 倍）、可删除；分量区旁有灰色小字"智能餐盘/称重勺（演示版请手动选择分量）"；底部有"手动加菜"（搜索下拉，300ms 防抖，数据来自 mock 食物表）。

* **FR-7**："餐前状态"卡片：心率滑块/手动输入（默认 78）、情绪四按钮（平静/焦虑/疲惫/烦躁），存 localStorage。

* **FR-8**："按住说话"语音按钮：使用浏览器原生 `SpeechRecognition`/`webkitSpeechRecognition`（真实能力），识别"我今天能吃什么"等简单话术后跳转食谱页；浏览器不支持时自动隐藏并在控制台留提示。

* **FR-9**：确认区底部一个大主按钮"看看这餐营养怎么样"，进入结果页。

### 结果页（`/result`）

* **FR-10**：顶部本次膳食评分 0–100，环形进度展示，红（<60）/黄（60–79）/绿（≥80）三色，配文字评级。

* **FR-11**：4 张大指标卡：热量(kcal)、钠(mg)、蛋白质(g)、钾(mg)；每张卡按红/黄/绿阈值配色，且**同时用颜色 + 图标 + 文字**传达状态（颜色非唯一通道）。钠卡为本页重点卡（视觉权重最高）。

* **FR-12**："这餐钠占全天预算"可视化（ECharts）：本餐钠**约**多少毫克（所有拍照估算数值一律带"约"字）主柱，标出单餐 800mg **演示参考线**（文案注明"参考线，不是医学限值"）、占全天 2000mg 预算的比例（百分比大字），超标段红色；钠数字旁同时给**食盐当量**（钠 mg ÷ 400 ≈ 盐 g，如"约 1600mg 钠 ≈ 4g 盐，差不多一啤酒瓶盖"）；下方一条"本餐钾摄入"对比条（对比全天 3600mg **努力目标（PI，非治疗达标线）**，钾充足绿色，不用"越满越好"的强暗示），条下灰字安全提示（默认："肾不好或正在吃普利/沙坦类降压药，补钾先问医生；别自己吃补钾片，低钠盐（氯化钾代盐）也要先问大夫"；画像 `renalKRestriction=true` 时升级为醒目提醒"按您的情况，富钾食物和低钠盐都要控制，按大夫交代的吃"，且该对比条不渲染"再补一点"式引导）；图角标注"演示数据"。文案均为膳食口径，不出现血糖相关指标。

* **FR-13**：规则解释卡列表：每卡含标题、一句口语化建议（禁用医学术语，如"这顿有点咸，下次少放一勺盐"）、规则编号小字（如 `HTN_Sodium_High`）、证据出处灰色小字（如"《成人高血压食养指南（2023）》"）。规则至少覆盖：钠超标（红/黄两档）、蛋白质不足、蔬菜不足、钾不足、正向鼓励（清淡达标餐）；文案随 `htnStatus` 个性化（confirmed/mild\_risk/high\_risk 强化"连续监测血压、再淡一点"，none/未评估用保持预防口径）；**`renalKRestriction=true` 时不生成任何"钾不足/建议补钾/多吃高钾"规则**（R2.2 安全规则）。

* **FR-14**：🔊"听一听"大按钮：`speechSynthesis`、zh-CN、语速 0.9，朗读本餐总结；受全局语音开关约束；朗读时按钮可停止。

* **FR-15**：减盐替换建议 chips（DASH 低钠高钾方向，如"咸菜配粥 → 凉拌新鲜黄瓜"、"红烧放酱油 → 清蒸蘸少许豉油"、"白灼菜多放葱姜蒜，少放盐"，含 tip 文案）；推荐食谱卡片 3 张（菜名、低钠/高钾等标签、营养摘要），点击可进食谱库对应详情。

* **FR-16**：当餐前心率 >100 或情绪为"焦虑"时，顶部多一条温和提示："您现在心率有点快，先歇两分钟慢慢吃，饭后散步15分钟会更舒服。"

* **FR-17**：底部按钮："保存这餐"（写入 mock 餐次、触发设备数据联动、跳转首页并提示）、"再拍一餐"（放弃当前结果回首页）。

* **FR-18**：页面含临床免责声明小字："本结果仅为膳食建议，不替代医生诊断。"

* **FR-19**：宽屏结果页左右分栏（左：评分/指标卡/规则；右：钠预算图/替换/推荐）；窄屏单列堆叠。

### 健康数据页（`/health`，硬件模拟）

* **FR-20**：5 张大卡片（数字加大加粗），每卡右上角灰色"演示数据"标签；**血压卡置顶且尺寸放大**（本页视觉主角）：

  1. 血压卡（置顶放大，模拟蓝牙血压计 + 手动记录合并；**家庭自测口径**）：最近 7 天早晚血压折线（收缩压/舒张压两条线），按家庭阈值分级着色——<135/85 绿、135–159/85–99 黄、≥160/100 橙、≥180/120 红；135/85 markLine 标注"家里测的警戒线"，卡上一句灰字解释"在医院里量的标准是 140/90，家里量 135/85 以上就要留意"；"今晨 128/82"式大字；模拟设备数据与手动录入记录同图展示（手动点样式区分、tooltip 标"手动记录"）；卡上"记一下血压"大按钮（见 FR-40）；副标题/提示按 htnStatus 差异化（confirmed 规律服药提醒、mild\_risk/high\_risk 连续监测建议、none 保持预防口径）；当周出现 ≥180/120 记录时卡顶显示就急诊红色提示条。
  2. 心率/情绪卡（模拟手环）：静息心率大字 + 最近情绪记录，与首页"餐前状态"联动显示（手动录血压时若填了心率也并入心率展示）。
  3. 步数卡（模拟手环）：今日步数大圆环 + 活动量等级（6000 步/天为达标线）。

* **FR-48 多账号与数据隔离（R2.2 新增）**：
  * **真实模式**：register/login 返回不透明 token（格式由后端定，前端只存取），存 `ndh_auth_v1={uid,phone,name,token,loginAt}`；axios 拦截器自动带 `Authorization: Bearer <token>`；401（未登录/过期）统一清会话并跳 `/login`；所有业务资源由后端按 uid 隔离，前端不接受越权数据假设。
  * **mock 模式（本机模拟同一套行为）**：账号表存 `ndh_accounts_v1`（`{uid,phone,name,passwordHash,salt,createdAt}`；密码用 WebCrypto SHA-256 + 每账号随机 salt 散列，**绝不存明文**；登录做常量时间比较）；会话同样写 `ndh_auth_v1`（token 为随机模拟串）；**所有业务 localStorage 键按 uid 命名空间隔离**（如 `ndh_profile_v1:<uid>`、`ndh_meals_v1:<uid>`、`ndh_bp_log_v1:<uid>`、`ndh_meds_v1:<uid>`、`ndh_devices_v1:<uid>`、`ndh_device_data_v1:<uid>`、`ndh_premeal_v1:<uid>`、`ndh_settings_v1:<uid>`，语音等纯设备偏好可不隔离），storage 封装统一拼键，业务代码不直接接触命名空间；已登录手机号不可重复注册（给中文提示）；退出只清会话不清数据；切换账号后看到的是各自独立的画像/餐次/血压/服药数据。
  * **一键体验**：使用固定演示 uid（`demo`）与确定性演示数据集，与任何注册账号物理隔离；重置演示数据只重置 demo 命名空间（若当前登录为演示账号）或当前账号命名空间（FR-28）。

* **FR-49 真实识别链路与手动兜底（R2.3 新增）**：
  * **真实模式**：拍照/相册图片经 `utils/image.ts`（canvas 压缩 1024px/JPEG0.8 + EXIF 方向校正，零新增运行时依赖）后以 multipart 上传 `POST /api/recognize`，带 Bearer token；loading 期间可取消；识别结果与 mock 场景同构，进入既有 FR-6 确认区。
  * **失败降级（三级，不阻断老人记录）**：①网络错误/超时 → 中文提示"没连上，再试一次"并保留图片可重试；②后端返回识别失败（422/无法识别）→ 提示"这张没认出来，手动选一下也一样"，直接进入确认区并可"手动加菜"；③后端未部署/接口不存在 → mock 模式行为（五场景）照常可用，页面不报错白屏。
