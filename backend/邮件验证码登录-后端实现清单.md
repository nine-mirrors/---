# 后端任务：邮箱验证码登录（正式环境发信）

> 给后端同学：前端已按本文档实现完毕，**无需前端配合改动**。你按此实现并部署后，前端只需切换环境变量即可联调（见文末）。
> 完整契约原文：`frontend/docs/api/_s01-auth.md` §1.2、§2.3、§2.4。本文档如与契约冲突，以契约为准。
> 全局约定（务必先读）：`frontend/docs/api/api-contract.md` §0.2、§0.3。

---

## 一、要实现的接口（共 2 个）

| # | 方法 | 路径 | 鉴权 | 作用 |
|--- |------ |------|------|------|
| 1 | POST | `/api/auth/email/send` | 不需要 | 发送 6 位邮箱验证码 |
| 2 | POST | `/api/auth/login/email` | 不需要 | 验证码登录，**未注册自动建号** |

> 全局约定：成功响应**直接返回裸数据**（不要包 `{code, data}` 外壳）；失败统一返回 `{"code": "错误码", "message": "中文提示"}`。

### 接口 1：发送验证码

**请求**

```json
{ "email": "wangayi@163.com", "scene": "login" }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| email | string | 是 | 邮箱，入库前 `strip().toLowerCase()` |
| scene | string | 否 | 目前固定 `login`（登录/注册复用一个场景） |

**成功响应（HTTP 200）**

```json
{ "ok": true }
```

⚠️ **邮箱无论是否已注册，都返回 `{ok:true}`**，防止接口被用来枚举哪些邮箱注册过；未注册邮箱可以静默不发信。

### 接口 2：验证码登录（未注册自动建号）

**请求**

```json
{ "email": "wangayi@163.com", "code": "123456" }
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| email | string | 是 | 邮箱 |
| code | string | 是 | 6 位数字验证码 |

**成功响应（HTTP 200，与注册/密码登录完全同体）**

```json
{
  "token": "eyJhbGciOi....(JWT)",
  "user": { "uid": "u_xxx", "email": "wangayi@163.com", "name": "王阿姨" }
}
```

**自动建号规则**：邮箱未注册时直接创建账号并签发 token，不要让老人再走注册流程。
- `name` 默认取邮箱 @ 前的本地名，超过 20 字截断（如 `wangayi@163.com` → `wangayi`）
- uid 由服务端生成；email 加唯一索引

### 错误码一览

| HTTP | code | message | 触发条件 |
|------|------|---------|----------|
| 400 | `EMAIL_FORMAT_INVALID` | 请输入正确的邮箱地址 | 邮箱格式错误 |
| 429 | `RATE_LIMITED` | 发送太频繁，请稍后再试 | 触发频控（仅接口 1） |
| 400 | `EMAIL_CODE_INVALID` | 请输入 6 位验证码 | code 不是 6 位数字 |
| 422 | `EMAIL_CODE_INCORRECT` | 验证码错误或已过期 | 验证码不匹配 / 已过期 / 已使用 |

错误响应体示例：

```json
{ "code": "RATE_LIMITED", "message": "发送太频繁，请稍后再试" }
```

## 二、验证码生成、存储与失效规则

| 项 | 要求 |
|----|------|
| 长度/字符集 | **6 位随机数字**（不足 6 位前面补 0），用密码学安全随机源生成 |
| 存储 | **存服务端**，建议 SQLite 表 `email_codes(email, code, expires_at, used, created_at, ip)`；不要放 JWT、不要返给前端 |
| 有效期 | **10 分钟** |
| 失效时机 | ① 验证成功立即作废；② 同一邮箱再次发送，旧码立即作废 |
| 校验通过后 | 签发 JWT（见第四节） |

## 三、发信要求

### 邮件内容（适老！用户是 60+ 长辈）

- **标题**示例：`【营养膳食助手】您的登录验证码 123456`
- **正文**：验证码用**超大字号**（建议 ≥32px）单独一行展示，周围留白；不要放外链按钮以外的复杂内容
- 正文需写明：10 分钟内有效、非本人操作可忽略
- 纯文本或简单 HTML 均可，不需要前端出模板

### 发信通道（二选一）

| 方案 | 适用 | 备注 |
|------|------|------|
| SMTP | 快速上线、量小 | Python 推荐 `aiosmtplib`；QQ/163 用的是**授权码，不是登录密码**，需在邮箱设置里开启 SMTP 服务获取 |
| 事务邮件服务 | 正式运营、送达率要求高 | 阿里云邮件推送 / 腾讯企业邮 SES 等 |

**配置全部走环境变量，严禁硬编码进代码/仓库：**

```
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_USER=xxx@163.com
SMTP_PASSWORD=授权码（不是邮箱密码）
SMTP_FROM=营养膳食助手 <xxx@163.com>
JWT_SECRET=随机长字符串
```

⚠️ 发信域名必须配置 **SPF / DKIM**，否则验证码邮件大概率进垃圾箱——老人收不到等于功能不可用。

## 四、JWT 要求（验证码登录成功后签发）

| 项 | 约定 |
|----|------|
| 算法 | HS256 |
| claims | `sub` = uid（字符串）、`iat` 签发时间、`exp` 过期时间；**不要放邮箱等隐私** |
| 有效期 | **30 天** |
| refresh token | **不做**，过期后前端引导重新登录 |
| 密钥 | 环境变量 `JWT_SECRET`，严禁硬编码 |
| 推荐依赖 | `pyjwt` 或 `python-jose[cryptography]` |

---

## 五、频控（必须实现，前端倒计时只是体验，不能当真）

| 维度 | 限制 | 超限响应 |
|------|------|----------|
| 同一邮箱两次发送间隔 | ≥ 60 秒 | 429 `RATE_LIMITED` |
| 同一邮箱每日发送量 | ≤ 10 次 | 429 `RATE_LIMITED` |
| 同一 IP 每日发送量 | ≤ 10 次 | 429 `RATE_LIMITED` |

## 六、完成后自测清单（6 条全过再通知前端联调）

- [ ] 1. 用**真实邮箱**（建议 163、QQ 各一个）请求接口 1，能收到邮件，标题正确、验证码大字清晰
- [ ] 2. 10 分钟内用收到的码请求接口 2，登录成功并拿到 JWT
- [ ] 3. 同一个验证码用第二次 → 422 `EMAIL_CODE_INCORRECT`
- [ ] 4. 60 秒内重复请求接口 1 → 429；当天第 11 次 → 429
- [ ] 5. 用**从未注册的邮箱**收码登录 → 成功，users 表自动新增一行，name 为 @ 前缀
- [ ] 6. 随机填一个不存在的邮箱请求接口 1 → 仍返回 `{ok:true}`，不泄露用户是否存在
- [ ] 附：错误邮箱格式 → 400；错码/过期码 → 422；邮件不在垃圾箱（SPF/DKIM 生效）

## 七、联调方式（你部署好之后）

1. 把后端 HTTPS 地址发给前端；
2. 前端修改 `frontend/.env.production`：
   - `VITE_USE_MOCK=false`
   - 删除 `VITE_ALLOW_MOCK_BUILD=true`
   - `VITE_API_BASE_URL=https://你的后端地址`
3. 重新构建部署前端，共同走一遍上面的自测清单。

> 注意：开关切成 false 后是**全量真实模式**，不只登录，`frontend/docs/api/_s02-business.md` 里的业务接口也会同时开始请求后端。若业务接口尚未就绪，建议先在测试环境联调，不要直接切生产。
