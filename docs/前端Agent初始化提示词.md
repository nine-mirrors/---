> 用法：把下面「====」之间的全部内容发给前端 Agent。这是纯前端工程，所有后端接口用 mock 数据实现，可独立运行。

帮我从零开发一个**纯前端 Vue3 工程**（不需要真实后端，所有接口用本地 mock 数据实现，要求后续能一键切换到真实 API）。这是一个**响应式网页应用**（不是 App、不是小程序），以笔记本浏览器演示为主，同时自适应平板/手机宽度。

## 一、项目背景

项目名：营养膳食助手。面向**患 2 型糖尿病合并轻度高血压的自理老人**，在笔记本上本地运行演示。核心流程：老人对饭菜拍照 → 系统识别食物并估算分量 → 计算营养（热量、血糖负荷 GL、钠、钾、蛋白质）→ 结合健康画像触发规则 → 用大字、口语化的方式给出解释和替换食谱。

## 二、技术栈（固定，不要换）

- Vue 3 + Vite + Vue Router + Pinia
- Element Plus（组件库，中文）
- ECharts（图表）
- axios（请求封装，mock 与真实 API 共用同一套函数签名）
- 纯 JS 即可，不上 TypeScript
- 工程输出到 `D:\code\---\frontend`（团队 Git 仓库，**只在 frontend/ 目录内操作，不要动 backend/、data/、docs/ 目录**）
- 开发服务器默认 http://localhost:5173；npm 已配置淘宝镜像，要求 `npm install` 后 `npm run dev` 可直接运行
- 浏览器只要求兼容最新版 Chrome/Edge，不需要兼容 IE

## 三、必须实现的页面（6 个，含硬件模拟页）

5 个一级入口：**拍照 / 健康 / 周报 / 食谱 / 我的**。宽屏（≥1200px，笔记本演示主场景）用左侧固定竖向导航栏（图标+中文文字）；窄屏（<768px）用底部 Tab 导航；中间宽度自适应。

1. **拍照记录页（首页）**
   - 大按钮"拍一拍今天的饭菜"：调用 `navigator.mediaDevices.getUserMedia` 打开摄像头，视频预览 + 拍照按钮；同时提供"从相册选择"上传兜底
   - 拍照后在前端用 canvas 压缩到最长边 1024px、JPEG 质量 0.8
   - 模拟识别过程：显示 1.5 秒 loading 动画，然后返回 mock 识别结果（多道菜）
   - **识别确认区**：每道菜显示名称、置信度、分量选择（小/标准/大 三个大按钮，对应不同克数）、可删除；分量区旁标注小字"智能餐盘/称重勺（演示版请手动选择分量）"；底部有"手动加菜"（搜索下拉，数据来自 mock 食物表）
   - 一个大主按钮"看看这餐营养怎么样"
2. **结果页**
   - 顶部：本次膳食评分（0-100，环形进度，红/黄/绿三色）
   - 5 张大指标卡：热量(kcal)、血糖负荷 GL、钠(mg)、蛋白质(g)、钾(mg)；每张卡按红/黄/绿配色，**同时用颜色+图标+文字**表达（不能只靠颜色）
   - **"预计餐后血糖反应"图（演示核心亮点）**：ECharts 折线，根据本餐 GL 生成餐后 2 小时血糖模拟曲线（高 GL 高尖峰、低 GL 平稳），并叠加一条"采纳主食替换建议后"的虚线对比曲线；图角标"模拟数据"
   - 规则解释卡列表：每张卡显示标题、一句口语化建议、规则编号（小字）、证据出处（灰色小字，如"WS/T 652—2019"）
   - 🔊"听一听"大按钮：用 Web Speech API（`speechSynthesis`，zh-CN，语速 0.9）朗读总结
   - 主食替换建议（chips 形式，如"白米饭 GI83 → 燕麦饭 GI42"）
   - 推荐食谱卡片（3 张，含菜名、标签、营养摘要）
   - 按钮："保存这餐"、"再拍一餐"
3. **健康数据页（硬件依赖功能，全部纯前端模拟）**：卡片式布局，见下方第六节
4. **周报页**：ECharts 展示最近 7 天的 GL 柱状图、钠摄入柱状图、评分折线图；下方"饮食分"小结（摄入不足/过量/多样性三个维度的简化分数）和一句本周建议
5. **食谱库页**：标签筛选大按钮（全部/低钠/低GL/高蛋白/富钾/易咀嚼），食谱卡片网格；点击卡片弹出抽屉，显示配料（克数）、做法步骤、每份营养
6. **我的（画像）页**：表单——昵称、年龄、性别、身高、体重、病史开关（2型糖尿病/高血压）、活动量（少/中/多）、牙口（好/一般/不好）、口味（清淡/一般/重口）、忌口；保存到 localStorage；页面显示自动算出的 BMI 和每日蛋白质目标（体重×1.2 g/kg）；下方有"我的设备"入口（见第六节）和"重置演示数据"按钮

**模拟生理状态模块（纯前端，无真实硬件）**：首页放一个"餐前状态"卡片，心率（滑块/手动输入，默认 78）、情绪（平静/焦虑/疲惫/烦躁 四个大按钮），存 localStorage。当心率 >100 或选"焦虑"时，结果页顶部多一句温和提示："您现在心率有点快，先歇两分钟慢慢吃，饭后散步15分钟会更舒服。"

## 四、响应式布局与适老化设计要求（硬性）

**响应式（网页应用，先保证笔记本宽屏效果）：**
- 断点（用 CSS 媒体查询 + Element Plus 栅格）：
  - ≥1200px：宽屏，笔记本演示主场景；内容最大宽度 1280px 居中；结果页左右分栏（左：指标/规则，右：血糖曲线/推荐）；卡片网格 3–4 列
  - 768–1199px：两列布局
  - <768px：单列纵向堆叠，导航变底部 Tab
- 字号用 rem/clamp 相对单位；所有 ECharts 图表宽度 100% 自适应容器并监听窗口 resize
- 摄像头预览区最大宽度 720px 居中；表格在窄屏改为卡片纵向堆叠

**适老化（工信部适老化规范，硬性）：**

- 正文基准字号 20px，标题更大；无衬线字体
- 行高 1.6；主按钮高度 ≥56px，圆角，点击区域 ≥44px
- 文字与背景对比度 ≥4.5:1；配色：红 `#d93025`、黄 `#f59e0b`、绿 `#1e8e3e`、主色用稳重的墨绿 `#0e7a5f`
- 每页只有一个主操作按钮；导航扁平、层级不超过 3 层
- 所有提示口语化、不使用医学术语（如不说"血糖负荷超标"，说"米饭有点多，血糖容易升得快"）
- 提供"语音播报"全局开关，位置固定

## 五、Mock 数据与接口契约（前端按此建 mock，后端将来照此实现）

封装 `src/api/` 模块，每个接口一个函数；用环境变量 `VITE_USE_MOCK=true` 控制走 mock 还是真实 `http://127.0.0.1:8000`。

- `POST /api/recognize`（上传图片）→ 返回识别结果：
```json
{"detected":[{"kind":"food","id":"012401x","name":"米饭（蒸）","confidence":0.96,"weightG":200,"gi":83},
{"kind":"dish","id":"tomato_egg","name":"番茄炒蛋","confidence":0.88,"weightG":150,"gi":null}]}
```
- `GET /api/foods/search?q=米饭` → 食物数组 `[{id,name,category,gi,energyKCal,protein,CHO,Na,K}]`
- `POST /api/evaluate`，请求 `{"items":[{"kind":"food","id":"012401x","weightG":200}],"profile":{...}}`，返回：

## 六、硬件依赖功能的前端模拟（演示模式，重点）

真实产品中依赖外部硬件、本原型用纯前端模拟的功能，统一做进"健康"页和结果页。**所有模拟数据必须在卡片右上角标注"演示数据"灰色小标签**（答辩时明确说明这是产品形态演示，不误导）。

**健康数据页**包含以下卡片（大卡片、数字加大加粗）：

1. **血糖卡（模拟 CGM 动态血糖仪）**：当日血糖曲线（ECharts 折线，正常区间 3.9–7.8 mmol/L 用绿色背景带标出），显示空腹值、餐后 2h 值；最近一餐 GL 高时餐后出现明显尖峰
2. **血压卡（模拟蓝牙血压计）**：最近 7 天早晚血压折线，正常 <140/90 绿色、超标黄/红；显示"今晨 132/85"式大字
3. **心率/情绪卡（模拟手环）**：静息心率数值 + 情绪记录，与首页"餐前状态"联动
4. **步数卡（模拟手环）**：今日步数大圆环 + 活动量等级
5. **睡眠卡（模拟手环）**：昨夜睡眠时长、深浅睡比例条
6. **体重卡（模拟智能体脂秤）**：近 30 天体重曲线 + BMI 大字

**数据联动要求（关键，形成"吃→指标→改"的演示闭环）**：
- 写一个纯前端 mock 数据生成器（`src/mock/deviceData.js`），首次进入生成 7 天历史基线
- 保存餐次后，模拟数据随之变化：高 GL 餐 → 当餐血糖曲线尖峰升高；近期钠摄入高 → 血压缓慢升高；采纳推荐食谱后 → 后续曲线改善（正向反馈）
- 所有模拟数据存 localStorage

**"我的→我的设备"页**：模拟设备管理列表（CGM 血糖仪、血压计、手环、体脂秤、智能餐盘），每项有"已连接/未连接"开关（纯前端状态）；断开后健康页对应卡片显示"设备未连接，点击查看"占位。

**可选增强**：首页加"按住说话"语音按钮（用浏览器原生 `SpeechRecognition` / `webkitSpeechRecognition`，这是浏览器真实能力，不是 mock），能识别"我今天能吃什么"等简单话术并跳转食谱页。

## 八、术语速查（界面文案一律用中文，缩写首次出现要带解释）

| 缩写 | 含义 / 界面处理建议 |
|---|---|
| GI | 血糖生成指数（0–100），数值越高升糖越快，>70 为高；界面写"升糖指数 GI" |
| GL | 血糖负荷 = 碳水克数 × GI ÷ 100，同时考虑吃多少和升糖快慢；≤20 较安全；界面写"血糖负荷 GL" |
| kcal | 千卡（大卡），热量单位 |
| mg / g | 毫克 / 克 |
| mmol/L | 血糖单位，健康人餐后 2h 应 <7.8，血糖曲线正常区间画 3.9–7.8 |
| BMI | 身体质量指数 = 体重kg ÷ 身高m² |
| CGM | 动态血糖仪（贴在手臂上连续测血糖的设备），血糖卡副标题注明"模拟 CGM 设备" |
| T2D / HTN | 2 型糖尿病 / 高血压（内部字段名，界面显示中文） |
| 钠 | 食盐的主要成分，约 393mg 钠 ≈ 1g 盐 |
| API | 前后端数据接口；mock 指用假数据模拟接口 |
| TTS | 语音合成（把文字读出来），用浏览器自带 Web Speech API |
| 演示数据 | 所有非真实采集的数据（血糖、血压、识别结果等）必须挂的标签 |
